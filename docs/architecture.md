# Архитектура Book Meet

Book Meet остаётся единым приложением для одного сервера, но внутри разделён на модули. Это сохраняет простое развёртывание в Plesk и позволяет позже вынести отдельные части в сервисы без переписывания продукта.

## Клиент

- `app/navigation` — маршруты страниц и единый стек поп-апов.
- `app/services` — HTTP-клиент и раздельная загрузка данных приложения.
- `app/components` — переиспользуемые интерфейсные блоки по предметным областям.
- `app/screens` — страницы каталогов, профилей, чатов и материалов.
- `app/hooks/useBookMeetController.tsx` — связывает модули и состояние текущей сессии; бизнес-логику следует постепенно переносить из него в feature-hooks.

## Сервер

- `server/index.js` — запуск Express, общие защитные заголовки, проверка Origin и ограничение частоты запросов.
- `server/api.js` — существующие предметные маршруты; новые крупные группы маршрутов добавляются отдельными router-модулями.
- `server/modules/bootstrap-router.js` — независимые endpoints начальной загрузки.
- `server/modules/content-security.js` — строгая очистка пользовательского HTML.
- `server/modules/image-storage.js` — проверка и сохранение изображений, безопасная обработка внешних адресов.
- `server/modules/request-limits.js` — общие лимиты изменяющих запросов.
- `server/data.js` — MySQL-запросы и сборка DTO; поддерживает выбор секций данных.
- `server/security.js` — пароли, сессии, TOTP и резервные коды.

## Загрузка приложения

Вместо одного постоянно повторяемого тяжёлого ответа клиент параллельно получает:

1. `/api/bootstrap/session` — идентификатор сессии и состояние профиля.
2. `/api/bootstrap/catalog` — пользователи, книги, публикации, события и поводы.
3. `/api/bootstrap/social` — дружба, подписки, сообщения, уведомления, реакции и блокировки.
4. `/api/bootstrap/moderation` — жалобы, доступные только администратору.

Старый `/api/bootstrap` сохранён для совместимости входа, регистрации и старых клиентов.

## Навигация поп-апов

Каждая карточка, отдельное уведомление и форма жалобы имеют постоянный URL. При открытии следующего материала предыдущий остаётся в стеке истории, но скрывается. Закрытие возвращает предыдущий поп-ап; если его нет — исходную страницу. Переход из диалога во вложение работает по той же схеме. Фоновая страница берётся из сохранённой точки входа и не меняется при обновлении данных в реальном времени.

## Граница дальнейшего разделения

Микросервисы сейчас не нужны. Кандидатами на отдельные процессы позже могут стать только измеримо нагруженные области: обработка импорта, изображения, уведомления и поиск. Решение принимается по метрикам, а не заранее.
