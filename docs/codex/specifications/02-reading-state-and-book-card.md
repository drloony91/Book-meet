# ТЗ 2. Состояние чтения и единая карточка книги

Статус: реализовано и локально проверено; production deployment выполняется по exact-artifact процедуре.
Очередь: 2 из 6.
Сложность: средняя–высокая; меняются модель пользовательской книги, исторические циклы и все точки открытия карточки.
Зависимость: ТЗ 1, особенно единое определение книги из собственной библиотеки.

## 1. Цель

Сделать статус и прогресс чтения единым пользовательским состоянием, которое одинаково отображается и редактируется во всех карточках книги. Подготовить достоверную историю завершений для статистики, целей и будущих reading sessions.

Отдельного статуса «Перечитываю» нет. Повторное чтение выполняется обычным статусом «Читаю», но предыдущее завершение сохраняется в истории.

## 2. Статусы

Канонический набор:

- `want` — «Хочу прочитать»;
- `reading` — «Читаю»;
- `read` — «Прочитано»;
- `abandoned` — «Брошено»;
- `postponed` — «Отложено».

### 2.1. «Хочу прочитать»

- Дополнительные обязательные поля отсутствуют.
- Пользовательские rating, дата завершения и активный прогресс не показываются.
- Предыдущая история завершений не удаляется.

### 2.2. «Читаю»

Поля:

- переключатель «Главы / Страницы»;
- «Вы прочитали»;
- «Всего глав/страниц»;
- «Мысли, цитаты, впечатления».

Все поля необязательны. Если заполнена только одна сторона прогресса, процент не вычисляется. Значения должны быть целыми неотрицательными числами, `current <= total`, `total > 0`.

Для глав и страниц хранятся отдельные пары значений. `progressUnit` указывает последнюю успешно заполненную/изменённую пару и является источником отображаемого процента. Если пользователь позднее меняет вторую пару, активной становится она.

Процент:

- вычисляется как `floor(current / total * 100)`;
- ограничивается диапазоном 0–100;
- не хранится как независимая редактируемая величина;
- показывается плашкой «Прочитано N%» на обложке во вкладке «Читаю»;
- во вкладке книги «Читатели» заменяет текст о последней главе.

### 2.3. «Прочитано»

Обязательные поля:

- оценка 0,5–5 с шагом 0,5;
- краткий отзыв;
- месяц прочтения;
- год прочтения.

День не хранится и не запрашивается. Кнопка «Сохранить» неактивна до заполнения всех полей.

При успешном переходе в `read` создаётся или завершается исторический цикл чтения. Книга попадает в статистику месяца/года завершения.

### 2.4. «Брошено»

- Необязательное поле «Краткий отзыв».
- Rating и дата завершения отсутствуют.
- Сохранённый прогресс может оставаться в БД для будущего продолжения, но не показывается в краткой карточке статуса «Брошено».

### 2.5. «Отложено»

Необязательные поля:

- комментарий;
- месяц;
- год.

Допустимы комбинации:

- месяц + год;
- только месяц — сервер подставляет текущий год пользователя;
- только год — месяц остаётся `NULL`;
- оба поля пусты.

Если выбранный период уже прошёл:

- дата подсвечивается красным;
- пользователь получает одно уведомление;
- повторные bootstrap/refresh не создают дубли;
- изменение даты сбрасывает флаг отправленного уведомления;
- уведомление остаётся, даже если пользователь скрывал других пользователей, поскольку это собственное системное уведомление.

Период считается прошедшим:

- месяц+год — с первого дня следующего месяца;
- только год — с 1 января следующего года;
- только прошедший месяц текущего года — сразу после сохранения.

## 3. Переходы между статусами

### 3.1. Общие правила

- Выбор статуса открывает системный popup с соответствующими полями.
- До нажатия «Сохранить» фактический статус не меняется.
- «Отмена», Back и закрытие popup возвращают прежний статус и значения.
- API выполняет status transition и запись зависимых полей одной транзакцией.
- Поля, не относящиеся к новому статусу, не должны случайно участвовать в DTO или валидации.
- Исторические завершения не удаляются при смене текущего статуса.

### 3.2. Повторное чтение

- Если книга была `read`, а пользователь выбирает `reading`, начинается новый reading cycle.
- UI по-прежнему показывает «Читаю», без отдельной метки «Перечитываю».
- Предыдущее завершение и его месяц/год сохраняются.
- Новое завершение создаёт вторую запись истории и может учитываться как ещё одна завершённая книга в статистике/целях.
- Текущая библиотечная карточка по-прежнему одна.

### 3.3. Автосохранение внутри открытой карточки

Личный блок книги разрешает менять данные без открытия полного редактора.

- Изменения отправляются debounce-autosave после 600–1000 ms покоя.
- Показать состояния «Сохранение…», «Сохранено», «Не удалось сохранить».
- Ошибка оставляет локальные значения и даёт кнопку повтора.
- При закрытии во время активного запроса дождаться результата либо показать предупреждение.
- Смена статуса всегда требует явного «Сохранить»; autosave применяется только к полям уже активного статуса.

## 4. Единая карточка книги

Если каноническая книга находится в библиотеке viewer, между автором и вкладками показывается личный блок.

### Для `reading`

- переключатель «Главы / Страницы»;
- две пары полей прогресса;
- поле «Мысли, цитаты, впечатления»;
- процент;
- autosave;
- кнопка «Сохранить заметку» появится в ТЗ 3.

### Для `read`

- оценка;
- краткий отзыв;
- месяц/год завершения;
- autosave после прохождения полной клиентской и серверной валидации.

### Для `abandoned`

- краткий отзыв;
- autosave.

### Для `postponed`

- комментарий;
- месяц/год;
- красное состояние просроченной даты;
- autosave.

### Действия в шапке

- слева от «Редактировать» — текущий статус как dropdown/action;
- «Редактировать» открывает полный редактор с теми же значениями;
- «Удалить» удаляет книгу только из библиотеки viewer;
- «Пожаловаться» отсутствует;
- изменения в полном редакторе сразу отражаются в личном блоке и наоборот.

## 5. Вкладка «Читатели»

Удалить отдельную вкладку «Хотят прочитать». В «Читатели» включить:

- читающих;
- прочитавших;
- желающих прочитать.

Метки:

- reading — «Читает сейчас · N%», если процент известен, иначе «Читает сейчас»;
- read — «Прочитано» и rating, если он есть;
- want — «Хочет прочитать»;
- abandoned/postponed в эту вкладку не включаются, если пользователь не имеет исторического завершения.

### Сортировка

Если viewer имеет `reading` и процент:

1. reading-пользователи по минимальной абсолютной разнице процентов;
2. read;
3. want.

Если viewer `read`:

1. read;
2. reading по убыванию процента;
3. want.

Если viewer не добавил книгу либо имеет `want`:

1. want;
2. reading по возрастанию процента;
3. read.

Если viewer `abandoned` или `postponed`, использовать его сохранённый процент, если он существует; иначе алгоритм `want`.

При равенстве сортировать по `displayName`, затем по `userId` для стабильности.

## 6. Модель данных

Добавить следующей последовательной миграцией поля в `user_books`:

- `reading_status` с новым allowlist;
- `chapters_current INT UNSIGNED NULL`;
- `chapters_total INT UNSIGNED NULL`;
- `pages_current INT UNSIGNED NULL`;
- `pages_total INT UNSIGNED NULL`;
- `progress_unit VARCHAR(16) NULL` (`chapters/pages`);
- `postponed_month TINYINT UNSIGNED NULL`;
- `postponed_year SMALLINT UNSIGNED NULL`;
- `postponed_notified_at DATETIME NULL`.

Существующий `last_read_chapter` мигрировать в `chapters_current`; `chapters_total` остаётся `NULL`. Существующий `reading_comment` продолжает хранить «Мысли, цитаты, впечатления»/комментарий текущего статуса.

Добавить `reading_cycles`:

- `id`;
- `user_id`;
- `book_id`;
- `started_at`;
- `completed_month`;
- `completed_year`;
- `completed_at` техническое, nullable;
- `status` (`active/completed/abandoned/postponed`);
- timestamps.

Требования:

- не более одного active cycle на `(user_id, book_id)`;
- user и book cascade;
- завершённые циклы сохраняются после удаления книги из пользовательской библиотеки до окончательного удаления аккаунта, если это допускает текущая privacy policy; иначе их удалять вместе с user;
- исходные `read_month/read_year` остаются быстрым current projection до отдельного решения об их удалении.

## 7. API

Предпочтительно оставить owner-scoped маршруты:

- `PATCH /api/books/:id` — изменение статуса/полей существующей библиотечной книги;
- `DELETE /api/books/:id` — удалить из своей библиотеки;
- `POST /api/books` — добавить каноническую книгу в библиотеку.

`PATCH /api/books/:id` принимает:

- `readingStatus`;
- rating/shortReview/readMonth/readYear;
- chaptersCurrent/chaptersTotal;
- pagesCurrent/pagesTotal;
- progressUnit;
- readingComment;
- postponedMonth/postponedYear;
- top3.

Ответ возвращает полный viewer book DTO, а не только `bookId`, чтобы controller не собирал состояние вручную.

Сервер обязан:

- валидировать allowlist и условные обязательные поля;
- нормализовать только-месяц до текущего года;
- не принимать `current > total`;
- вычислять процент сам;
- атомарно обновлять cycle;
- создавать due notification один раз;
- broadcast-ить только после commit.

## 8. Privacy и видимость

- Количество страниц/глав — пользовательские данные, не канонические свойства `books`.
- Другим пользователям разрешено видеть процент и краткий статус в «Читатели».
- Сырые значения глав/страниц и текст «Мысли, цитаты, впечатления» не показываются другим пользователям, кроме опубликованных заметок из ТЗ 3.
- Block и age filtering применяются к списку читателей.
- Скрытие из ТЗ 4 не скрывает сам профиль читателя, но скрытый пользователем материал не влияет на этот список.

## 9. Desktop/mobile

- Desktop: личный блок располагается между автором и вкладками карточки.
- Mobile: тот же блок является частью отдельной страницы книги и не открывает вложенные popup для каждого текстового поля.
- Popup смены статуса на mobile занимает отдельный workflow route с Back/Cancel.
- Процент на обложке не перекрывает Top-3 и 18+.
- Dropdown статуса доступен с клавиатуры и screen reader.

## 10. Критерии приёмки

1. Все пять статусов сохраняются и восстанавливаются после refresh/re-auth.
2. `read` невозможно сохранить без rating, short review, month и year.
3. Cancel не меняет статус и поля.
4. Последняя изменённая валидная единица определяет процент.
5. Значение `current > total` отклоняется и клиентом, и сервером.
6. Просроченный postponed-период красный и создаёт одно уведомление.
7. Повторный переход `read → reading → read` сохраняет два completion cycle без статуса «Перечитываю».
8. Одна и та же книга во всех точках открытия использует одинаковый viewer state.
9. Другой пользователь видит процент, но не личный текст.
10. Сортировка «Читателей» соответствует всем трём алгоритмам viewer.

## 11. Проверки

- Migration structure и real MySQL verification.
- API tests всех status transitions и условной валидации.
- Transaction tests cycles и dedupe postponed notification.
- Owner/friend/stranger/blocked/minor matrix.
- Desktop/mobile browser flows: dropdown, popup, Cancel, autosave, direct route, Back.
- Regression Top-3, удаление из библиотеки, rating aggregation ТЗ 1.
- Полный `pnpm verify`, `pnpm verify:db`, обязательный browser suite перед handoff.

## 12. Не входит в очередь

- цели и публичные заметки;
- полки;
- таймер и длительность чтения;
- live reading presence;
- изменение канонического количества страниц книги.
