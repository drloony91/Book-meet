# ТЗ 3. Цели чтения, заметки и книжные полки

Статус: реализовано и локально проверено; production deployment не выполнен.
Очередь: 3 из 6.
Сложность: высокая; внутри обязательны три независимых подэтапа: цели, заметки и полки.
Зависимость: ТЗ 2 — статусы, проценты и история завершений.

## 1. Цель

Превратить библиотеку из списка книг в инструмент планирования и осмысленного чтения: добавить цели, защищённые от спойлеров заметки и публичные тематические полки.

Функции выпускаются тремя отдельными подэтапами внутри очереди:

1. цели;
2. заметки;
3. полки.

Каждый подэтап должен проходить самостоятельную проверку; нельзя выпускать полку как material без готовых permissions и moderation hooks.

## 2. Цели чтения

### 2.1. Точка входа

В собственной библиотеке рядом с «Открыть статистику чтения» добавить кнопку «Цели».

- Desktop: popup.
- Mobile: отдельная workflow page с Back и явной кнопкой закрытия.

### 2.2. Экран целей

Сверху показываются существующие цели отдельными кнопками:

- «Цель на сентябрь 2026»;
- «Цель на 2027 год».

После списка — разделитель и переключатель:

- «Цель на месяц»;
- «Цель на год».

До выбора типа поля создания не показываются.

### 2.3. Месячная цель

Поля:

- месяц — от текущего месяца до декабря текущего года;
- количество книг — целое число больше нуля.

Текст:

`В [месяц] я прочитаю [N] книг`.

Расчёт темпа:

- для будущего месяца использовать полное количество календарных дней;
- для текущего месяца использовать оставшиеся дни, включая текущий день;
- `daysPerBook = remainingDays / targetCount`;
- целое значение показывать как «по одной книге за N дней»;
- дробное значение показывать диапазоном `floor–ceil`, например 1,5 → «за 1–2 дня»;
- если цель превышает количество дней, показывать «больше одной книги в день», не делить на ноль.

Кнопка «Поставить цель» активна только при валидных полях.

### 2.4. Годовая цель

Поля:

- год;
- количество книг.

Доступные годы:

- следующий календарный год — всегда;
- текущий год — только в январе и феврале.

Текст:

`В [год] я прочитаю [N] книг`.

Расчёт:

- следующий год — 12 месяцев;
- текущий год в январе — 12 месяцев, включая январь;
- текущий год в феврале — 11 месяцев, включая февраль;
- показатель выводить как книги в месяц;
- дробное значение округлять до одного знака для пояснения, но месячный план распределять целыми книгами.

### 2.5. План по месяцам и перенос отставания

Для годовой цели сервер/общая доменная функция рассчитывает месячный план динамически.

Алгоритм на начало каждого месяца:

1. определить общее количество completion cycles в уже завершённых месяцах целевого периода;
2. `remaining = max(0, target - completedBeforeCurrentMonth)`;
3. распределить remaining равномерно по текущему и оставшимся месяцам;
4. целый остаток распределять начиная с ближайших месяцев;
5. прошедшие месяцы не переписывать;
6. не создавать обязательную cron-мутацию первого числа — план является вычисляемой проекцией.

Месячная цель не переносится за пределы выбранного месяца.

### 2.6. Статистика цели

Нажатие на существующую цель открывает статистику чтения с выбранным периодом.

- Плановый столбец обведён пунктиром.
- Над ним указан план.
- Фактическая высота строится по completion cycles.
- Если результат нулевой, внизу явно отображается `0`.

Цвет фактического столбца:

- меньше 50% — ненасыщенный красный;
- 50–80% включительно — ненасыщенный жёлтый;
- 81–99% — ненасыщенный зелёный;
- 100% и выше — насыщенный зелёный.

Без цели остаётся текущий синий график. Переключатель статистики «Книги / Время» будет добавлен в ТЗ 6 после появления reading sessions.

### 2.7. Данные и API целей

Таблица `reading_goals`:

- `id`;
- `user_id`;
- `goal_kind` (`month/year`);
- `target_count`;
- `target_month NULL`;
- `target_year`;
- timestamps;
- unique `(user_id, goal_kind, target_year, target_month)` с нормализацией годовой цели.

API:

- `GET /api/reading-goals`;
- `POST /api/reading-goals`;
- `PATCH /api/reading-goals/:id`;
- `DELETE /api/reading-goals/:id`;
- `GET /api/reading-statistics?year=&month=`.

Цели строго приватны и принадлежат текущему пользователю.

## 3. Заметки без спойлеров

### 3.1. Создание

В личном блоке книги со статусом `reading` рядом с полем «Мысли, цитаты, впечатления» добавить кнопку «Сохранить заметку».

Кнопка активна, когда:

- текст непустой;
- существует валидная активная пара прогресса;
- вычислен percentage snapshot.

Перед записью показать подтверждение:

- «Сохранить заметку?»;
- прогресс в исходной единице;
- процент в скобках;
- полный текст;
- «Сохранить» и «Отмена».

Сохранение заметки не очищает автоматически текущее поле «Мысли, цитаты, впечатления».

### 3.2. Вкладка «Заметки»

Добавить в карточку книги вкладку «Заметки» с переключателем:

- «Мои заметки»;
- «Все заметки».

Заметки отображаются небольшими inline-карточками без отдельного modal:

- автор и avatar;
- дата;
- зафиксированный прогресс и процент;
- текст;
- owner delete/edit при необходимости;
- report для чужой заметки.

Лайки, комментарии, сохранения и репосты заметок в эту очередь не входят.

### 3.3. Спойлер-гейт

Viewer видит:

- все собственные заметки;
- при `read` — все чужие заметки;
- при `reading`, `abandoned` или `postponed` с известным процентом — чужие заметки с `note.progressPercent <= viewer.progressPercent`;
- при `want`, отсутствии книги или неизвестном проценте — только заметки с `0%`;
- скрытых/заблокированных авторов — согласно viewer-aware правилам: заметки скрываются как материалы автора.

Текст во вкладке:

«Вы увидите заметки других пользователей по мере прочтения книги, чтобы не поймать спойлер. Указывайте свой прогресс чтения в карточке книги.»

Фильтрация обязательна на сервере. Клиент не должен получать закрытый текст заметок.

### 3.4. Данные и API заметок

Таблица `book_progress_notes`:

- `id`;
- `user_id`;
- `book_id`;
- `reading_cycle_id NULL`;
- `body`;
- `progress_unit`;
- `progress_current`;
- `progress_total`;
- `progress_percent`;
- timestamps.

Ограничения:

- текст 1–3000 символов;
- percent 0–100;
- progress snapshot после создания не меняется при изменении текущего прогресса;
- user/book cascade;
- note доступна только для читаемой книги и допустимого возраста.

API:

- `GET /api/books/:id/notes?scope=mine|all&cursor=`;
- `POST /api/books/:id/notes`;
- `PATCH /api/book-notes/:id` — меняет только текст;
- `DELETE /api/book-notes/:id`;
- `POST /api/reports` с новым target kind `book_note`.

## 4. Книжные полки

### 4.1. Переключатель библиотеки

Удалить «Плитка / Список». Плитка становится единственным видом обычной библиотеки.

Добавить «Книги / Полки»:

- desktop — на месте старого view switch;
- mobile — над переключателем статусов;
- чужая библиотека показывает тот же переключатель;
- режим не разделяет полки по `want/reading/read`.

### 4.2. Карточка полки

Содержит:

- название;
- описание до 500 символов;
- первые четыре книги в одну строку;
- количество книг;
- автора полки.

Открытие:

- desktop — popup;
- mobile — отдельная route page.

Внутри:

- название;
- описание;
- книги списком;
- обложка, название, автор, пользовательская оценка;
- пользовательское описание книги на полке до 500 символов;
- если описание отсутствует, показать каноническую аннотацию.

### 4.3. Создание и редактирование

Рядом с «Добавить книгу» добавить «Создать полку».

Форма:

- название — обязательно, 1–120 символов;
- описание — до 500;
- блок «Добавьте книги из своей библиотеки»;
- поиск по автору или названию только среди своей библиотеки;
- повторяемые поля выбора книги по сценарию event book selector;
- описание каждой выбранной книги до 500;
- одна книга не может повторяться;
- минимум одна книга для публикации полки.

Desktop использует popup, mobile — workflow page. Редактор сохраняет всё одной транзакцией.

### 4.4. Действия с полкой

Полка является новым material kind `shelf` и поддерживает:

- like;
- comment;
- save;
- repost после ТЗ 4;
- отправку другу;
- report;
- owner edit/delete.

Чужая полка доступна любому авторизованному пользователю с учётом block/hide/age rules.

### 4.5. «Добавить книги в библиотеку»

Над action bar полки добавить кнопку.

Подтверждение:

«Книги, которых ещё нет в вашей библиотеке, будут добавлены со статусом “Хочу прочитать”.»

Сервер одной транзакцией:

- пропускает существующие книги;
- добавляет отсутствующие как `want`;
- не меняет статусы существующих;
- не добавляет недоступные/удалённые книги;
- применяет 18+ ограничения;
- возвращает `addedCount`, `skippedExistingCount`, `skippedUnavailableCount`.

### 4.6. Данные и API полок

Таблица `book_shelves`:

- `id`;
- `owner_user_id`;
- `title`;
- `description`;
- timestamps.

Таблица `book_shelf_items`:

- `shelf_id`;
- `book_id`;
- `position`;
- `description`;
- unique shelf/book;
- shelf cascade, book set null либо controlled removal согласно общей политике каталога.

API:

- `GET /api/users/:id/shelves?cursor=`;
- `GET /api/shelves/:id`;
- `POST /api/shelves`;
- `PATCH /api/shelves/:id`;
- `DELETE /api/shelves/:id`;
- `POST /api/shelves/:id/add-to-library`.

Расширить polymorphic allowlists reactions/saves/comments/reports/material search значением `shelf`. Проверка readable shelf выполняется до любой операции.

## 5. Navigation и realtime

- Route полки: `/shelves/:id`.
- Mobile create/edit: `/create/shelf`, `/edit/shelf/:id`.
- Close/Back возвращает точный background route и выбранный режим «Полки».
- Успешные CRUD, reactions и comments broadcast-ят после commit.
- Goal/note/shelf autosave не должен перетирать более свежий bootstrap state.

## 6. Критерии приёмки

### Цели

1. Доступны только допустимые месяцы/годы.
2. Pace корректен для текущего и будущего месяца.
3. Годовой остаток перераспределяется без изменения прошедших месяцев.
4. Цвета и пунктир соответствуют границам 49/50/80/81/99/100%.
5. Повторное завершение из нового cycle учитывается отдельно.

### Заметки

1. Snapshot не меняется после обновления текущего прогресса.
2. Viewer на 40% не получает текст заметки 41% даже в API.
3. `read` видит все допустимые заметки.
4. `want`/без книги видит только 0%.
5. Block/hide/18+ применяются сервером.

### Полки

1. Переключатель одинаков на desktop/mobile и в чужой библиотеке.
2. Первая карточка показывает максимум четыре обложки.
3. Создание/редактирование сохраняет порядок и descriptions.
4. Batch add добавляет только отсутствующие книги как `want`.
5. Полка проходит все material actions и moderation.
6. Удаление полки каскадно удаляет её items/actions, но не книги каталога.

## 7. Проверки

- Real MySQL migration/FK/cascade tests.
- Unit tests календарной математики и распределения целей.
- Viewer matrix заметок: owner/less progress/equal/more/read/want/no book/blocked/hidden/minor.
- Transaction tests shelf CRUD и batch add.
- Browser desktop/mobile: goals, chart, note gate, books/shelves routes, Back/refresh/re-auth.
- Regression material likes/saves/comments/reports и strict diagnostics.

## 8. Не входит в очередь

- likes/comments/reposts заметок;
- приватные полки;
- совместное редактирование полок;
- статистика времени чтения;
- Telegram/email delivery целей;
- live co-reading.
