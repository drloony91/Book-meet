# Аудит безопасности Book Meet

Дата проверки: 2 августа 2026 года.

## Исправлено в этой ветке

- XSS в HTML публикаций: регулярное выражение заменено строгим allowlist-санитайзером. Сценарии, обработчики событий, опасные элементы, атрибуты и стили удаляются на сервере.
- Подмена изображений: формат PNG/JPEG/WebP теперь определяется по сигнатуре содержимого, а не по MIME из Data URL или HTTP-заголовка.
- SSRF через редиректы: каждый переход внешней книжной страницы и обложки проверяется до нового сетевого запроса; переход на другой домен блокируется.
- Неограниченные ответы внешних сайтов: добавлены ограничения размера HTML и изображений до чтения и после чтения тела.
- Массовые изменяющие запросы: добавлены отдельные лимиты для авторизации, сообщений, загрузок и остальных операций записи.
- Transport security: в production добавлен HSTS; уже существующие CSP, `nosniff`, запрет фреймов, ограничение разрешений и проверка Origin сохранены.
- Зависимости: аудит обнаружил high-уязвимость обхода `server.fs.deny` в Vite; Vite обновлён с 8.0.13 до исправленной 8.0.16, повторный аудит не нашёл известных уязвимостей.
- Секреты и локальные данные: cookie-файл, uploads, env-файлы, release/deploy-архивы и временные каталоги исключены из Git.

## Уже было реализовано

- Пароли хешируются scrypt с индивидуальной солью.
- В базе хранится SHA-256 хэш токена сессии, cookie имеет `HttpOnly`, `SameSite` и `Secure` в production.
- Административные операции повторно проверяют роль на сервере.
- TOTP допускает ограниченное временное окно, резервные коды хранятся только как хэши.
- SQL-запросы используют параметры вместо склейки пользовательских значений.

## Оставшиеся эксплуатационные задачи

- Настроить регулярные резервные копии MySQL и проверяемое восстановление.
- Хранить production-секреты только в переменных Plesk, периодически менять `GOOGLE_CLIENT_SECRET` и административные учётные данные.
- Подключить журналирование ошибок и алерты по HTTP 5xx/429, времени запросов и размеру очередей.
- Перед публичным запуском провести динамическое сканирование отдельного staging-окружения и ручную проверку прав доступа с тестовыми ролями.
